# 货源与单件利润测算

建立可复算的候选成本方案，接受人工测样和报价回填。无需 1688 key 即可用用户数据运行；实时货源价格由已授权的数据通道补充。

## 读取路径

- 处理价格、费用和测样：读[数据合同](references/data-contract.md)，用[输入模板](assets/input-template.json)与[人工测样表](assets/measurement-sheet.md)。
- 运费和利润计算：读[计算方法](references/calculation.md)，使用 `scripts/calculate.mjs`，不要另外写一份口算公式代替脚本。
- 方案比较和交付：读[报告合同](references/report-contract.md)。
- [example.json](assets/example.json) 是完全虚构的演示，报价、汇率和商品均不能用于真实决策。
- [batch-example.json](assets/batch-example.json) 演示商家包装与测样包装两个方案的批量比较，全部数字为虚构。

## 工作流

1. 确认市场、销售币种、商品成交收入、买家运费收入和每单销售单元数。若只给 TK 商品链接，先准备 `tiktok-supplier-matching` 的候选货源映射。
2. 将选定供应 SKU、采购量与阶梯报价换算为每个销售单元的采购成本。样品价、量产报价及不同货源分别建方案。
3. 保存商家包装数据以便初筛；样品到手后由用户填写实际发货包装的毛重、长宽高、包内数量和包装版本。实测值不覆盖商家原值。
4. 读取对应目的国与有效期的物流报价；确认计重、进位、限重、尺寸/货物适用性及附加费。没有报价时不假定费率。
5. 声明每项成本为已确认、估算、未知、不适用或明确排除。平台扣点使用本次用户约定 6%，扣费基数默认商品成交收入并披露假设，可按用户政策修改。
6. 运行计算器；遇到待补费用、汇率缺失或运费不适用时，交付待补列表及已知成本，不给完整利润数字。
7. 数据齐全时输出按单和按销售单元的贡献利润、贡献利润率，以及包装/费率/报价变化的情景对比。结果始终属于预计贡献，不是净利润或结算单。

## 本地使用

在项目根目录运行（不联网、不读 key）：

```sh
npm run economics:calculate -- skills/tiktok-unit-economics/assets/example.json
npm run economics:calculate -- skills/tiktok-unit-economics/assets/batch-example.json
```

输入及结果为 JSON，方便 agent 根据用户自然语言、测样表或物流报价整理。批量使用 schema_version=1 和 cases 数组（每项为完整方案），逐项保留状态；不因一项失败丢弃其他结果，重复 case_id 会报错。

## 判断边界

- 价格、成本与运费必须按同一销售单元和计价币种归一化；真实汇率需要来源与日期。
- SKU 或包装变化后旧测量不自动沿用；整箱重量不能直接当单件重量，单件体积也不能直接乘件数当整箱外体积。
- 运费自动模型针对每订单一个已明确包装的包裹；多包裹、海外仓头程/尾程或其他合同计费先明确分摊，再使用手工每单运费模式。
- 缺失不等于零。只有用户确认不适用或明确排除的费用才可跳过；结果展示排除项。
- 测算不自动采购、发询盘、下单、买物流服务或修改售价。
