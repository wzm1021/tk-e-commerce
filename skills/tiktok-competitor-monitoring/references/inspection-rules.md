# 巡检规则 v1

- 频率：12 / 24 / 168 小时，从启用时或本轮入队时计算下一次；每日默认 24 小时。停机恢复只补一轮，不重放所有错过时点。UTC 用于调度与自然月预算，界面展示本地时间。
- GMV 默认同时满足 `abs(本期-基期) >= 1000`（店铺原币）和 `abs(本期/基期-1) >= 30%`；销量默认绝对变化 100 件和 30%。基期为 0 时只用绝对阈值。
- 默认连续 2 个相邻数据截止日越过同方向阈值才产生事件；配置 1 日时首个可比较的后续轮次即可触发。首次有效趋势只是基线。周频巡检建议用 1 次确认。
- 同指标同方向持续异常属于一个事件，不每天重复提醒。只有后续有效窗口回到阈值内或方向反转，才重新开始确认。缺失轮次不代表恢复。
- 商品首次有效列表只建立基线。以后首次观察到某商品进入前 10，产生一个事件；一生效监控内按商品 ID 去重，再次进入不重复提醒；不是上新监测。
- 每轮最多 3 次业务调用，正常采集消耗上限 3 个实时积分，缓存按平台现价结算。配置单轮预算仍需覆盖 3 积分。无自动分页或无限重试。
- 单轮预算通过任务预留强制执行，结束退回未用额度。月预算统计该监控在 UTC 入队月份的已花费及未完成任务预留，所有手动/自动轮次共用。同一监控不重叠运行；同幂等键重试返回原任务。
- 余额、连接、身份或数据异常保留失败原因；自动调度延后至少 1 小时，避免失败忙循环。暂停与删除不抹除历史账单和证据。
