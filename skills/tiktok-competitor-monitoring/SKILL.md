# 竞店监控

让用户知道哪家竞店发生了值得跟进的变化，并保留判断依据。默认每日巡检，先建立基线，只在有新事件时生成 AI 解读。

## 读取路径

- 首次执行读[共用规范](../../docs/fastmoss-analysis-contract.md)和[数据合同](references/data-contract.md)。
- 配置与判断读[巡检规则](references/inspection-rules.md)。
- 交付读[结果合同](references/result-contract.md)。
- 确定性采集计划、快照归一化和规则在 [monitor.mjs](scripts/monitor.mjs)；平台与独立执行复用这份代码。

## 执行顺序

1. 接收字符串 seller_id、市场、频率、单次与月度预算。选品中心一键添加时，从该报告已归档的候选事实读取店铺 ID、名称和市场，沿用默认巡检配置；缺少店铺 ID 或市场不猜测，已有监控复用且保留原规则与暂停状态。身份一旦绑定不能直接换店；基础信息必须与配置匹配。
2. 固定当前 skill 版本、规则、历史有效快照和已观察商品 ID。只从 FastMoss 取基础信息、28 日日趋势和近 7 日 GMV 商品榜前 10。
3. 归档原始响应与调用 ID，再运行脚本建立快照；采集时间、源更新时间、数据日期分别保存。字段变更、缺日、错误响应和身份冲突保留为质量问题。
4. 比较两个完整、连续、等长、不重叠的 7 日窗。源时区未知时保守排除最近两个 UTC 日期，明确源时区未知，不把抓取时间视作数据截止日。
5. 首轮建立基线。后续用幅度、绝对量、连续不同截止日确认和事件去重判断变化；同日重复采集不能增加持续天数。商品仅报告“首次观察到进入前 10”，不称新品或全店上新。
6. 规则生成事件后才可调用模型，读取本 skill 和固定事实。AI 只解释可能原因、替代解释及下一步，不能改写事实、阈值或调用额外实时工具。
7. 保存每轮状态、快照、事件、证据与实际费用。无变化不生成提醒；有问题展示运行异常。深入分析由用户进入竞店研究或经营诊断发起。

## 边界

- 缺失不补零；第一页消失不等于下架、缺货或销量下降；累计值不相减冒充日销量。
- 基期为零时只报金额/件数变化，增长率为空。不做币种换算、不拼跨市场店铺。
- 平台是调度与预算执行主体。暂停阻止后续调度，已运行任务保留结果；不在分析中自行创建外部定时任务或发送站外消息。
- 用户删除竞店监控时，先确认目标店铺和市场，再归档监控并移除后续调度；从监控列表移除但保留历史快照、事件、报告和费用。已提交任务继续处理并按实际用量结算，不因删除伪造退款。再次添加同店时创建新的监控记录。
- 达人、视频、价格、佣金和广告暂不生成自动事件，待真实字段与历史口径核验后扩展；可作为专项研究的待验证方向。
