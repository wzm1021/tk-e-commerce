# 经营异动诊断

先确认变化是否真实、影响多大，再定位可被数据解释的部分并提出下一步验证。数据不足时，“无法判断具体原因”是有效结论。

## 确定任务

- 接收店铺/商品 ID 或链接、异常指标、发生时间与用户看到的变化；区分 FastMoss 估算 GMV、平台订单、净收入等不同指标。
- 默认比较最近两个可用的完整 7 天；用户给定异常日期时围绕该日期选等长、尽量同星期结构的窗口，另保留日序列。
- 用户给出内部数值时同时保存其定义，不用 FastMoss 指标覆盖它。自家店身份、关键指标或目标期无法确定时先做可独立的数据检查，再问最小必要问题。

## 读取路径

- 首次取数：读[共用数据规范](../../docs/fastmoss-analysis-contract.md)和[取数指南](references/data-sources.md)。
- 判断真实变化、贡献和原因证据：读[诊断方法](references/methodology.md)。
- 诊断报告与排查单：读[交付模板](references/report-contract.md)。

## 工作流

1. **确认口径与完整性。** 排查身份错配、未完整日、时区、缺失/重复日期、累计/日增量混用和估算回补；发现不兼容先解释数据问题。
2. **确认异动。** 给出日趋势、绝对差值和有有效基数的相对变化，定位开始时间、持续性和是否由单日主导。
3. **定位可量化部分。** 先拆同口径 GMV 与销量，再按商品或销售渠道做单一维度对账；保持未覆盖差额可见。
4. **按假设补数。** 根据前一步线索选达人、视频、直播、广告、SKU 或品类背景；不一次性调用所有分析接口。
5. **分级解释。** 将直接数值贡献、关联线索和仍未验证的经营原因分开，列出相反证据及可推翻假设的检查。
6. **提出下一步。** 按影响规模、证据强度和验证成本给出最多 3 个优先排查动作，说明需要的数据、检查时间与结果判定。

## 判断边界

- 当前渠道占比或达人名单不等于历史变化；无基期证据不能归因于“达人流失”或“渠道下滑”。
- GMV/销量是平均单位成交金额，可能受价格、折扣或商品组合影响；没有订单数不叫客单价，没有曝光/点击不拆流量转化漏斗。
- FastMoss SKU 库存份额不证明真实缺货及其发生时间。限流、处罚、退款增加、履约中断等需要直接证据，不能作为默认解释。
- 同期相关与算术贡献不证明经营根因；修复建议根据证据强度限定，不能因弱线索就建议大幅停投或换品。
- 默认一次诊断 1 个主实体、深挖至多 5 个贡献分项、约 20 次业务调用。达到预算或只剩后台才能验证的原因时交付当前诊断和最小补数清单。

## 示例请求

- “这个店近 7 天 GMV 下跌，帮我找优先排查方向。”
- “销量没变但销售额下降，判断是价格还是商品结构变化。”
- “后台和 FastMoss 对不上，先确认口径再分析增长。”
