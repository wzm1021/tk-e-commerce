# 评论编码与改进决策

## 建立可复核记录

每条评论保存：产品/评论 ID、日期、星级、可识别 SKU、语言、短原文、必要译文、采样组、主题、正负/混合/不确定态度、严重性及编码备注。与任务无关的姓名、联系方式等不进入报告。

区分“文本明确表达”“根据语境推断”“无法判断”。星级仅为一项信号；五星文本也可能包含投诉，低星也可能评价快递而非商品。

## 起始主题表

根据实际评论合并或增加主题，不强迫套用全部分类。

| 主题 | 典型问题 | 可行动方向 |
| --- | --- | --- |
| 购买动机/满意点 | 场景、便利、礼赠、外观、性价比 | 已证实卖点与演示选题 |
| 功能/质量 | 无效、易损、稳定性、材料 | 复现验证、抽检、设计改进 |
| 适配/尺寸 | 尺码、兼容、容量、颜色差异 | 尺寸图、适配表、变体标识 |
| 使用困难 | 安装、清洁、操作、维护 | 说明书、FAQ、教程 |
| 预期落差 | 图片/文案与体验不同 | 核实页面承诺，补充真实限制 |
| 包装/履约 | 破损、漏件、延迟、错发 | 包装、配件清单、履约核查 |
| 售后体验 | 退款/客服响应方面的陈述 | 售后流程核查，不能直接算退货率 |

原因不明确时保留多种可能。例如“无法开机”可以提出设备故障和使用方式两条验证路径，不直接判断制造责任。

## 计数规则

- 主表主题占比 = 近期样本中提及该主题的唯一可分析评论数 / 近期样本唯一可分析评论数。
- 同一评论可有多个主题，所以各主题占比之和可超过 100%；同一评论同一主题只计一次。
- 定向高/低星补充样本单列例证和发现数，不与近期样本混成总体占比。用户只给差评时明确分母为所提供的差评文本。
- 空文本仅用于星级分布（若有评分），不进入文本主题分母；不同表各自注明分母。
- 没有 SKU 级完整分母时只报某 SKU 被提及的条数；不同商品评论量悬殊时并列 `n/N` 与采样范围，不靠原始问题条数排名。
- 时间变化必须用相同采样策略、可比周期并检查版本/变体变化。评论提交日不是缺陷发生日。

例：近期取得 20 条记录，其中 2 条重复、2 条无文本，得到 16 条可分析评论；其中 4 条谈尺寸、3 条谈安装，报告为近期文本样本 4/16 与 3/16。另取的低星补充 10 条不并入这两个分母。

## 优先级

不用无依据的固定权重合成“产品缺陷评分”。按以下次序解释优先级：

1. 严重性：可能造成伤害/商品无法使用的个案优先核查，即使频率低；这是调查优先级，不是已证实安全结论。
2. 证据强度：多条具体描述、跨时间重复、SKU 一致性，以及是否有明确反例。
3. 可操作性：信息澄清、演示、包装或产品调整能否解决；需要哪些内部验证。
4. 样本覆盖与成本：可比样本中的涉及面、预估工作量，成本未知写待评估。

每个建议连接“问题 → 原文证据 → 可能原因 → 改动 → 验证”。测试后应使用新同方法样本、客服分类或内部退货原因来评估，不承诺仅改文案就会提高评分。

## 写 FAQ 与页面文案

以真实问题为题，答案只使用已确认的规格、操作和限制。评论声称“防水”“医用”等不能成为产品已验证属性；事实未知时交付待确认答案与所需资料，而非可直接发布的宣称。

引文保持简短，给评论 ID、日期与必要原文/译文；不大量转贴原评论。将用户反馈翻译为建议时保留原意，不放大情绪。
