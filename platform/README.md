# 探阔 Tanviko 平台开发入口

生产工作台位于本目录。仓库根目录 `src/` 是电商数据客户端，`skills/` 是按租户发布的分析技能；历史设计原型未包含在公开版本中。

## 本地开发与验证

在 `platform/` 下执行：

```sh
npm ci
npm run dev       # 后端；需本地私密环境配置
npm run web       # 前端 127.0.0.1:4310；默认代理后端 127.0.0.1:9080
npm run check     # 检查导入、静态资源、模块语法及容器/服务入口
npm run build     # 同时构建用户端和管理端
npm test          # 单元、报告、SDK 等回归
```

可通过 `TIDELAB_API_TARGET` 指定开发代理。生产数据库凭据不要放入前端或代码库。三个 PostgreSQL 集成套件需要显式设置 `TEST_DATABASE_URL`，必须使用隔离验证数据库和无绕过 RLS 权限的应用角色；不允许使用业务数据库。未配置时会跳过这三个套件。测试文件串行执行，避免同一验证数据库的全局派发队列被其他套件抢占；套件内部的 32 并发、幂等和配额验证仍并发执行。SDK 测试使用本机回环测试服务，需要允许监听本机端口。

## 维护约定

### 竞店监控

工作台的「竞店监控」先绑定完整字符串店铺 ID 和市场，默认每日巡检。支持 12 / 24 / 168 小时间隔、暂停与启用、手动巡检、规则编辑、站内未读事件、最近 30 轮记录和巡检报告。周频使用 1 次确认；每日默认连续 2 个不同截止日确认。首版指标为 GMV、销量与近 7 日 GMV 商品前 10；不将榜单变化称为上新或下架。

选品中心的“候选商品”和商品依据详情提供“监控店铺”入口，从归档候选事实带入店铺 ID、名称和市场，使用现有默认巡检规则。服务端从报告读取身份并按工作区／店铺／市场去重；已有监控返回原记录，保留暂停状态与自定义配置。缺失或不可靠的店铺 ID／市场不自动创建，添加动作本身不重新采购数据。

店铺卡片与巡检详情提供“删除监控”，确认后归档记录、移出列表并移除后续调度。历史快照、事件、报告和费用保留，已提交的任务继续处理并按实际用量结算。删除后可从选品中心或手工重新添加同店，创建新的监控记录。

执行合同在 [`tiktok-competitor-monitoring`](../skills/tiktok-competitor-monitoring/SKILL.md)，其 `scripts/monitor.mjs` 同时供 API 和执行器使用。流程为：Worker 请求任务 → 数据库扫描到期监控 → 锁定监控并固定技能、规则与连接 → 预留单次预算 → 采集 3 个 FastMoss 接口 → 建立快照和确定性事件 → 有新事件时生成 AI 解读 → API 从归档证据重算 → 保存事件、报告并退回未用预算。租户自定义技能文字用于解释指导；自动事件仍由平台 v1 规则执行，不能用提示词覆盖事实判断。

- 新空间自动绑定技能；旧空间首次添加监控时发布缺失的初始版本，不覆盖已有绑定。编辑规则期间若已有未结束巡检会拒绝保存，避免混用基线；暂停不删除已入队任务。
- `shop_monitors`、`monitor_runs`、`monitor_requests`、`monitor_events` 启用并强制 RLS。全局 `monitor_schedule` 只存调度 ID 和到期时间；没有独立 cron 服务或进程内定时器。Worker 停机期间保留到期记录，恢复只补一轮，繁忙时按队列延后。
- 同一监控不重叠运行；手动请求即使复用已有任务，也保存幂等映射。单次上限通过原有任务预算预留强制执行，月预算按 UTC 入队月份计入已结算费用与未完成任务预留。采集/模型权限仍由网关核验。
- 首轮建立基线；缺失、陈旧、身份/货币冲突、空商品榜与结构变化会降级，不补零。当前数据源时区未知，趋势保守排除最近两个 UTC 日期；窗口与来源更新时间在快照中分别保存。
- 失败入队延后 1 小时，原因展示在监控卡片；在途费用不明时使用现有 `reconciling` 流程，未核对前不启动同一监控的新轮次。站外消息与自动经营操作未接入。

发布前应用 **009_competitor_monitoring.sql**，给应用角色授予新表的业务读写权限。应用、Worker 发行目录和 Agent 镜像需同步；镜像额外复制 `skills/tiktok-competitor-monitoring` 至 `/skills/tiktok-competitor-monitoring`，否则执行器无法加载共享规则。仅发布 skill 不能替代代码与数据库升级。

监控专项回归：`node --test test/monitoring.test.mjs test/monitoring-integration.test.mjs`。集成套件需配置隔离的 `TEST_DATABASE_URL`，校验调度并发、租户边界、预算、证据重算、幂等、取消与退款；使用合成响应，不采购真实数据。页面到执行器流程还应在隔离预览中验证，生产发布后再按实际授权范围验收供应商接入。

### 共用维护约定

- 页面放在对应 `features/` 下，用户端/管理端入口只挂载 App。业务状态由页面持有；跨页面共享的 hook、工具和 UI 分别放入 `hooks/`、`lib/`、`components/`。
- 共用层不能反向依赖 `features/` 或 `app/`。使用具体文件的直接导入，不增加汇总所有业务模块的 `index` 文件。全局样式在两个挂载入口各引入一次。
- 后端按职责修改现有模块。路由通过 `installXxx` 注册，由 `server.mjs` 组装；数据库事务、租户授权、费用结算仍在后端执行。当前是模块化单体，不是独立微服务。
- `common/` 保持无业务模块依赖；`infra/` 提供基础能力。`data/` 网关与任务、证据、账本有事务关联，目录分组不代表它们已经完全解耦；继续保留显式导入，避免隐式跨域副作用。
- 纯函数优先放在独立的契约/规则文件。CLI 和行政修复放入 `scripts/`，不能由服务启动入口自动执行。修改后按风险运行相应业务测试。
- 数据模型只用新 SQL 迁移变更。此次目录整理没有修改表结构、计费规则、租户技能绑定或报告内容规则。
- 租户 skill 仍从仓库根目录打包，新增 reference 时同步校验 schema 和来源契约。技能发布与代码发布使用各自版本机制。

## 运维入口与路径迁移

研究任务不设置整体运行时长上限。Worker 通过心跳续租控制执行权，新任务凭证随有效租约生效；取消、失联、单次接口超时和余额检查仍按原机制处理。研究结束后的在途调用全部结算后，平台继续校验并发布已保存草稿，保留真实中断原因；不能将结算完成直接视为研究失败。选品提交前复核只使用归档证据，避免重复采集拖延交付。

| 操作 | 当前入口 |
| --- | --- |
| 启动应用 / Worker | `npm start` / `npm run worker`，systemd 原路径保持不变 |
| 数据库迁移 | `npm run migrate` → `scripts/migrate.mjs` |
| 首次初始化 | `npm run bootstrap` → `scripts/bootstrap.mjs`，私密配置通过 stdin 输入 |
| 报告重渲染 | `WORKSPACE_ID=<id> REPORT_ID=<id> npm run report:rerender`（另需数据库和存储环境配置） |
| 历史数据快照回填 | `scripts/backfill-data.mjs` 的 `backfillData`，仅由明确的运维操作调用 |
| 已失败研究恢复 | `scripts/recover-failed-scouting.mjs` 的 `recoverFailedScouting` |
| Agent 镜像入口 | `/app/src/agent/agent-runner.mjs` |

旧的平铺实现路径已移除；外部脚本若直接导入 `src/db.mjs`、`src/core.mjs` 等，需按新目录调整。不要用兼容副本形成两套实现。仓库内测试与引用已同步迁移。

涉及模块目录、执行协议或 Agent 依赖的发布，必须同步匹配的应用、Worker 和 Agent 镜像：使用完整的新发行目录，防止残留旧模块。新任务启动前确认镜像包含 `src/agent/` 下的执行器、工具桥和两份提示词，核对静态资源摘要。纯静态更新和文档修订按实际依赖处理。保留旧发行目录及其镜像用于回滚；运行中的任务继续使用原镜像和已固定的技能快照。详细步骤见 [部署说明](deploy/README.md)。

用户选品流程为“新建选品研究 → 候选报告 → 选入机会池 → 进一步研究”。固定的“导入已有 60 品报告”按钮及空状态提示已移除；已保存的历史报告与后台历史导入兼容接口仍保留，不删除用户数据。

### 亚马逊选品

侧栏选择 TikTok Shop 或亚马逊。两平台共用任务与余额，分别固定技能、数据连接、证据和报告。亚马逊接入与部署步骤见 数据接入契约 `../docs/amazon-integration-contract.md`，应用追加迁移 `010_amazon_scouting.sql`。当前为 SellerSprite MCP 个人验证适配，正式 API 接入仍待文档与授权。
